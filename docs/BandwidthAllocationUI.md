# 带宽分配 UI 定稿

2026-10-02：用户在交互预览中查看“紧凑列表”后回复“可以的，就这样吧”。采用当前紧凑列表布局作为后续实现的设计依据。本阶段为 UI 确认；生产带宽控制尚未接入。

## 已确认界面

- 双向带宽池：分别展示 Mac mini → iMac 和 iMac → Mac mini 的配额总量、剩余容量与超额状态。
- 六个通道：网络画面、扬声器、摄像头、麦克风、iMac 硬盘、SD 读卡器；支持滑块与数值输入，同时显示 Mbps 和换算的 MB/s。
- 方向固定：画面／扬声器向 iMac，摄像头／麦克风向 Sender；硬盘／SD 的相同配额分别用于读写方向，不能把两个方向混成一个带宽池。
- “显示优先”“通话优先”“文件传输”三种预设；配额可自定义。
- 分配方式提供“空闲配额可借用”与“固定配额上限”。任一方向超额时禁止应用，保留明确提示。
- 预览链路包括千兆以太网和雷电示例；显示已分配部分及协议／稳定性余量。

## 示例值的边界

预览中的 900 Mbps 可分配容量、100 Mbps 余量和雷电 10 Gb/s 都是模拟参数，不是链路实测。用户调整过的配额也不自动成为生产默认值。实际版本须使用选定有线接口的有效容量，并与已有视频准入预算协调。

“应用到预览”只修改界面状态。实现生产控制后才能改为真正的应用动作；成功状态必须对应执行结果，不能只表示设置已保存。

## 后续实现约束

- 复用现有配对认证和有线接口绑定，不新增加密需求。
- 配额是限额／共享策略，不是保证设备能跑到相应速度；SD／硬盘还受物理设备与共享协议限制。
- 显示、音频与媒体服务内部的发送控制可分别接入；系统 SMB 的硬盘／SD 独立限速须先验证具体执行机制，不能只加滑块就声称生效。
- 区分发送与接收方向，保护音频／控制的必要余量；视频预算应与分配界面使用同一容量来源，避免重复预留。
- HDMI Rescue 不依赖网络配额；任何预算或限流故障不得破坏 Rescue Lock 和后台保活。
- 保持 Catalina 10.15.7 支持；不为界面定稿安装管理员服务、系统驱动或改变实际网络。

基础显示／HDMI Rescue 仍优先。本次仅记录已确认的设计，没有修改生产代码、重建测试包或执行真机测试。
