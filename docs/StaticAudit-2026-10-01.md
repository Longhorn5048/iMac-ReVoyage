## 结果

确认并修复了下列可行动问题。当前本地构建、静态分析和相关回归测试通过；这不代表整个项目已被证明没有漏洞或运行时泄漏。

| 问题 | 修复 |
| --- | --- |
| 接收端超大音频包使缓冲计数变负，并可能越界写入 | 拒绝超过 150 ms 或不完整 PCM 帧的包；保留有界队列和环绕写入 |
| 主连接未认证即可接收视频、键鼠和剪贴板消息 | 按用户授权升级双方协议，强制双向配对验证；没有匿名或旧协议回退 |
| 认证阶段可通过持续发送数据占用连接/事件循环 | 设置固定认证期限、限制未认证残留缓冲，每轮读取最多 8 次并在拒绝后立即结束读取 |
| 接收端显示尺寸可触发 Swift 整数转换或乘法崩溃 | 校验面板/模式/采集尺寸、HiDPI 尺寸关系和刷新率，再创建虚拟显示 |
| 解码器分配失败后解引用空指针；重配置失败仍标记可用 | 检查 extradata 分配，重配置前清除 opened 状态，失败后拒绝继续送帧 |
| 参数集解析失败可能改变当前 codec；截断的 NAL 长度前缀被忽略 | 失败时恢复 codec，严格拒绝截断 NAL，并在 reset 时释放帧引用 |
| 采集启动或唤醒重启期间断连，旧任务继续覆盖新会话 | 异步恢复后核对连接和管线身份；旧显示实例与新实例分离，停止迟到的采集流 |
| 音频回调从后台队列读取会话状态；停止后仍保留日志计时器 | 转换保持在有锁的音频队列，会话判断和发送切回 MainActor；停止时取消计时器 |
| 插件 manifest ID 可包含路径分隔符，导入时可能覆盖目录外文件 | 在拼接目标路径前校验 ID，只允许有界的 ASCII 文件名字符 |
| 网络解析器长度相加可能溢出，最终 sentinel 保存前未初始化 | 加入 size_t 溢出检查，安全增长容量并初始化最终 sentinel；无对齐要求地读取 Swift 长度字段 |
| 极大滚轮输入可能触发 Int32 转换崩溃；C 数字解析静默截断 | 转换前检查范围，拒绝 strtol 溢出或超出 int 范围的值 |
| 线缆测速可能无限等待，最后发送超时仍被算作成功 | 为背压等待设定超时，未发送完成时返回超时错误 |
| 字符串提取失败不保证输出初始化；语言文件 rewind 错误未检查 | 保证有效输出缓冲始终以空串初始化，检查文件定位结果 |

## 主连接认证协议

接收端通过 0x14 challenge 发送新的 32 字节随机 nonce，并声明 requiresSessionAuthentication=true。发送端发送 0x17 的 32 字节 HMAC-SHA256 证明，接收端验证后返回 0x18 的反向证明。双方使用不同方向的域字符串，避免证明反射及与设置/存储协议混用。

认证前接收端仅接受认证、心跳和关闭消息；显示资料在认证成功后发送。发送端也先验证接收端证明，再接受显示资料及控制消息。错误密钥、错误证明、重复认证或不支持认证的旧端点均被拒绝。每次连接使用新 nonce，认证期限不因收到心跳而延长。

**迁移要求：** 发送端和接收端均须更新，发送端须保存与接收端一致的配对码。原 mock_sender 已同步支持认证，可指定 --pairing-key-file。

**安全边界：** 此次提供连接身份验证，TCP 后续流量仍未加密，也未给每个数据包附加完整性标签。无法据此声称能防止窃听、主动中间人或转发攻击；仍应在可信、隔离的本地网络使用。TLS/逐包认证属于后续协议加固范围。
