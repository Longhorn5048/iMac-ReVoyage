# Sender 睡眠与 iMac 屏幕联动

日期：2026-10-08。源码已实现，自动联动默认启用，需要更新 Sender 和 Receiver；Receiver 继续支持 Intel / macOS 10.15.7。

## 使用行为

| 状态 | iMac 屏幕 | 串流与后台服务 |
|---|---|---|
| Sender 正常工作 | 亮屏显示 | 正常传输 |
| Sender 系统睡眠，或屏幕进入睡眠 | 息屏 | Sender 暂停视频/音频发送；Receiver、监听与独立服务继续运行 |
| Sender 唤醒 | 自动亮屏 | 恢复采集；连接失效时自动重连 |
| 用户此前手动息屏 | 保持手动选择 | 自动唤醒不撤销手动息屏 |
| 意外断网，没有睡眠通知 | 保持原有 Rescue Lock 亮屏等待 | HDMI Rescue 继续独立工作 |

关闭的是显示器电源，不是用黑色画面或亮度 0 模拟息屏，也不会令 iMac 主机睡眠。macOS 让 Sender 真正进入系统睡眠后，CPU 和网络传输自然暂停；应用进程保留。不能承诺整夜保留同一条 TCP 连接：Receiver 仍在 10 秒完全静默后回收旧连接，避免占住唯一客户端位置。睡眠状态保存在内存中，回收连接不点亮屏幕。

现有“串流时防止屏幕睡眠”选项继续生效；若希望 Sender 按系统空闲时间息屏，应关闭该选项。系统睡眠的采集恢复自动执行；原有“唤醒/解锁后重启采集”偏好继续控制解锁、退出屏保等额外恢复事件。显式停止会取消自动恢复，未连接的 Sender 不会因为唤醒自行新建连接。

## 实现方案

1. **睡眠通知**：Sender 通过 IOKit 接收系统睡眠/唤醒事件，屏幕睡眠通过 NSWorkspace 接收。系统睡眠前等待 Receiver 回执，并将系统睡眠延迟限制在最多 2 秒；注册不可用时退回 NSWorkspace 通知。API 生命周期依据 [Apple QA1340](https://developer.apple.com/library/archive/qa/qa1340/_index.html)。
2. **独立协议状态**：能力字段 `supportsSenderPower`；`0x3d` 为 `[awake, BE64 requestID]`，`0x3e` 为 `[awake, accepted, BE64 requestID]`。沿用现有直接连接与会话协商，不增加配对或权限流程。旧 Receiver 没有能力字段时不发送新指令。
3. **屏幕控制**：Receiver 分开记录手动息屏与 Sender 睡眠，任一要求息屏即释放显示保活；现有 Rescue 电源控制器执行 `pmset displaysleepnow`，主机保活继续持有。每个物理操作关联请求 ID；相同物理状态合并执行，回执等待本机操作结果；唤醒覆盖尚未完成的自动息屏，迟到结果不能改写新状态。
4. **暂停与恢复**：Sender 暂停视频发送、静态帧重发和音频发送；不把睡眠中的无帧当作采集故障。唤醒后恢复采集，丢弃休眠前静态帧并要求关键帧。连接失效时自动重连，尽量保留同一 Receiver、模式及刷新率的虚拟显示器；只有模式需要变化或显示器已失效时重建。
5. **恢复边界**：网络尚未恢复时，自动重试最长 60 秒；支持联动的 Receiver 必须回执 awake 状态且实际帧恢复，才结束恢复流程。显式停止立即取消重试；超时后保留错误，仍可手动连接。显示服务重启仍沿用既有“亮屏等待”的恢复策略。

## 验证与验收

自动验证不发出实际睡眠、亮屏、摄像头或输入操作：

- Sender 协议及采集连续性相关 XCTest：53 项，覆盖新报文、旧端能力缺省、系统/屏幕睡眠交叠、重复唤醒、停止取消恢复与空闲帧失效。
- Receiver session-gate：真实报文处理与本机电源回执路径，电源 API 和通知替代；覆盖睡眠中继续保持进程/会话、断连前未完成的息屏、断连后的亮屏、新旧回执竞争、手动息屏优先与失败回滚。
- Receiver 全量编译使用 x86_64 / macOS 10.15。
- Rescue 状态 75 项检查与电源控制器回归通过；所有电源操作均为替代实现。

目标机待验收（未经请求未执行）：

1. 连接 Mac mini 与 Catalina iMac，连续串流后让 Mac mini 进入系统睡眠；确认 iMac 背光关闭，Receiver/Rescue 进程仍在。
2. 分别睡眠 5 秒、超过 10 秒和 30 分钟后唤醒；确认无需手动连接即可亮屏、恢复视频及声音，检查扩展桌面窗口位置。
3. 仅让 Sender 屏幕息屏，再唤醒；反复快速睡眠/唤醒，确认旧息屏结果不会再次关闭已唤醒的屏幕。
4. 手动息屏后让 Sender 睡眠/唤醒；确认手动选择保留。睡眠期间显式停止 Sender，会话应保持停止。
5. 唤醒时延迟接通有线网络；确认在重试窗口内自动恢复。正常工作时直接拔线，仍应进入亮屏的 HDMI Rescue 等待状态。

源码验证不能证明目标 iMac 的实际背光电源行为、睡眠通知顺序或恢复耗时；这些需要上述双机验收。若睡眠前链路已不可用，Receiver 无法收到睡眠意图，将继续执行原有亮屏救援策略。
