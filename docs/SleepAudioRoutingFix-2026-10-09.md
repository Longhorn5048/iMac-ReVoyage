# 唤醒与系统音频输出联动修复

**音频部分已被独立 iMac 扬声器设备替代**：不再使用内建扬声器判断远端播放，当前行为见 [独立 iMac 输出设备](IMacSpeakerDevice-2026-10-09.md)。下文音频条目保留为此前方案记录，睡眠／唤醒修复继续生效。

## 修复行为

- Sender 唤醒后，支持电源联动的 Receiver 在 8 秒内未确认 awake，或采集在 12 秒内未恢复，将主动重建连接。每条新连接重新计算宽限时间，整体仍限制为 60 秒。显式停止取消恢复；保留既有虚拟显示器复用逻辑。
- Receiver 接到 awake 重试时，重新请求 Rescue 执行物理亮屏并等待回执，不再仅凭内存中的 awake 状态立即报告成功。手动息屏仍然优先。
- Sender 监听系统默认音频输出设备。只有内建扬声器路由允许向 Receiver 发送音频；耳机插孔、蓝牙、USB、HDMI、AirPlay、聚合及其他外部输出会关闭发送门禁。切回内建扬声器时按用户的“传输音频”设置自动恢复。未能读取输出设备时保持不发送。
- 同一内建音频设备上的耳机插孔、耳机 stream terminal 和 headphone data source 均纳入判定；监听路由变化，并每秒补查一次，覆盖驱动未发通知及睡眠后的设备重新登记。
- 系统采集音频本身仍与播放设备独立，本次通过发送门禁约束远端播放。切换时已提交的短音频队列可能自然播完（既有缓存预算为 150 ms）；不修改系统音量或用户音频开关。

## 验证

- Sender 全量 179 项 XCTest 通过，包含输出设备策略、切换后积压恢复不能重新放行，以及失效连接／采集超时的新增回归。
- Receiver 真实报文处理测试通过，覆盖睡眠断连、唤醒、重复 awake 请求再次触发物理操作、迟到回执及手动息屏优先；电源 API 均使用替代实现。
- Receiver 修改部分以 x86_64、最低 macOS 10.15 编译并与现有同版本依赖链接。
- 未执行双机、实际睡眠／亮屏或耳机操作。本次消除了已确认的代码缺口，不能由自动测试确认用户设备上的唯一触发原因。

## 安装与复测

更新包同时更新 Sender 和 Receiver，Receiver 侧使用安装脚本确保后台组件同步更新。先退出旧 Sender 再安装新版。

1. 正常串流后，让 Sender 睡眠超过 10 秒再唤醒，等待自动亮屏及恢复画面；若旧连接失效，应在恢复窗口内自动重连。
2. 播放同一段网页音频，在系统声音输出中切换有线耳机、蓝牙耳机或 USB 设备，确认 iMac 在旧短队列播完后停止发声；切回内建扬声器时恢复远端声音。
3. 关闭“传输音频”后切换输出或睡眠唤醒，确认不会自行恢复远端声音。
4. Receiver 手动息屏后重复 Sender 睡眠唤醒，确认手动息屏仍然保留。
