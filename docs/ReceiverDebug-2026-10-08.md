# Receiver 本地调试

Receiver 和 HDMI Rescue 支持 iMac 本地键盘快捷键，适用于 Intel / macOS 10.15.7；窗口需要获得键盘焦点。

- **D**：开关顶端两行串流信息栏，默认关闭。在 HDMI Rescue 也可开关。
- **R**：切换手动 HDMI Rescue／普通网络显示。后台仍接收和解码，网络音频及输入转发在 Rescue 期间暂停；再次按 R 恢复。没有 HDMI/UVC 画面时显示等待界面，R 仍可返回。物理息屏意图仍优先。
- D／R 的按下与释放留在本机；长按不会反复切换。Command／Option／Control 组合键继续原有处理，不占用这些快捷键。
- Sender teardown、断线和无视频只重置会话，不结束 Receiver 或监听端口。后续连接可重新开始串流；手动 Rescue 选择保持到再次按 R 或 Receiver 重启。

## 指标

| 信息 | 定义 |
| --- | --- |
| 分辨率 | 最近实际解码／上传的画面尺寸，不使用请求尺寸冒充实际结果 |
| 色彩／编码 | 当前输出 NV12、8 位、4:2:0，H.264／HEVC／RAW；HW／SW 是解码帧的实际观察结果；不推断未传输的色域／HDR 信息 |
| 接收／提交 fps | 约一秒窗口内完整视频报文和 SDL 图像提交次数，按实际采样间隔计算；不是面板扫描速率 |
| 面板 Hz | 接收端报告的当前面板刷新率，未知时显示 — |
| 接收→提交延迟 | 最终呈现帧的完整报文处理开始到 SDL 提交返回的本机平均耗时；不包含 Sender 采集、编码、链路和面板扫描，不能视为双机端到端延迟 |
| 带宽 | 实际 socket 读取字节换算为 Mbps，包含视频、音频和控制报文，计数不含 TCP/IP 头与重传 |
| 丢包率 | TCP 上未提供可验证的网络丢包／重传统计，显示未测量／—，不伪报 0% |
| 合帧 | 上传成功但被同批新图像替代的帧比例，是主动去积压，不是网络丢包 |
| 解码错误 | 当前 Receiver 进程累计解码失败次数 |

信息栏只在数据或窗口尺寸变化时重新栅格化，视频每帧复用短纹理，原画面不缩放或移动。Receiver 将信息文本及手动 Rescue 状态随现有本机显示通知同步给独立 Rescue；R 的返回键通过本机通知送回 Receiver。

## 验证

快捷键、统计、SDL 按键路由／信息栏缓存、会话切换／teardown 重连和 Rescue 无 HDMI 返回有本地替身回归，所有电源和显示操作均不触碰硬件。尚未执行目标 iMac 的实际键盘、画面叠加及 HDMI 切换验收。
